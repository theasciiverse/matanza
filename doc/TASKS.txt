04. Solve problems with the handler for the Telnet protocol

Done: 100%
Author: Azul

The src/telnet.c file has one bug.  It reads:

/* TODO: There are problems when a packet gets cut in the middle of a telnet
 * command.  They should be fixed. */

This happens because the code assumes that the arguments to the Telnet
options (TELOPT_TTYPE, TELOPT_NAWS, TELOPT_LINEMODE) are always read during
the same call to the recv function.  However, if they are broken into
multiple packages and then read in different calls to recv, they won't be
in the same buffer and wreckage will occur.

The code should be changed to store the characters for the arguments in
fields of the MatTelnet structure as they are read.  Currently, it attempts
to copy them all into their appropriate location when they have been read
completely.

the MatTelnet structure.

12. Allow different types of ships in a given universe

Done: 85%
Prioridad: 4
Complejidad: 3
Duración: 4
Encargado: Galactus
Dependencias: 8

To make things interesting, it should be possible to specify different
parameters such as speed, health, number of bullets and missiles and so on
per ship.  Each different ship should be given a specific image.

This should be configurable through the XML file.

The changes required to do this are:

a. Create shiptype.c and shiptype.h files with the descriptions for the
ships.  There should be a structure MatShipType there, containing all the
information for a given type of ship.  We will create different instances
of the MatShipType class at runtime as specified in (d).  You will want to
add fields such as health, max_speed, acceleration, can_brake, an array
num_bullets with the maximum number of bullets the player can shot of every
specific type, the image for the ships of this type and so on.  Each
shiptype should have a unique (for a given universe) ID.

b. Modify ship.c and ship.h and have the functions there specify a given
MatShipType for every ship.  This should probably be specified as one field
in the MatShip structure: a pointer to a MatShipType object.  You'll
probably need to modify not only the constructors but also many other
functions to have them respect the information in the MatShipType object.

c. Change universe.c and universe.h so every universe has a hash with types
for the ships.  We will register the available ship types in that hash,
giving each a unique ID.  You can clone the way each universe has a hash
with all its images (each image having a unique ID).

d. Modify the XML reader (in usluniverse.c) to accept a given <ShipType>
tag inside the <Universe> tag.  The ShipType tag must contain enough
parameters to initialize a given MatShipType structure.  When the parser
finds one ShipType tag, it should create a MatShipType structure and
register it in the universe.

e. Make it possible for the rendering widget (defined in widgetrender.c and
widgetrender.h) to receive focus and also make it possible to associate a
callback function with its key event.  This should be done in a manner
similar to how one registers handles for the focus-in/focus-out events for
buttons (widgetbutton.c) and text entries (widgettext.c).  In
mat_mainmenu_start (in mainmenu.c) register one such handler for the render
widget that makes it possible to cycle through the images for all the ship
types available in the universe.  This way the telnet player will be able
to select the ship he wants to use.
